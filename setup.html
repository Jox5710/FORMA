FORMA Setup

Free forever, no server, no monthly cost

The form lives on GitHub Pages. Google Apps Script — free with your Gmail — receives each submission and writes it into a Google Sheet in your Drive. Your dashboard reads that same sheet. Nothing to pay, nothing to maintain.

One-time setup: about 6 minutes.

01

Create the sheet

Open sheets.new, name it FORMA Clients, and rename the first tab to Clients (bottom-left tab, double-click).

Copy the long ID from the address bar — the part between /d/ and /edit.

02

Add the script

In that sheet: Extensions → Apps Script. Select everything in the editor and delete it, paste the code below in its place, then replace the two lines at the top with your sheet ID and a private access code you invent.

Paste it into the file that is already there — usually Code.gs. Adding it as a second file breaks the whole project: Apps Script joins every .gs file into one scope, so a second copy declares SHEET_ID twice and every request answers SyntaxError: Identifier 'SHEET_ID' has already been declared. If you see that, open the Files list and delete the duplicate so only one remains.

03

Deploy it

Deploy → New deployment → Web app. Set exactly these two:

Execute asMe (your Gmail)
Who has accessAnyone

Google will ask you to authorise — click Advanced → Go to project (unsafe). It is your own script; that warning is normal. Copy the Web app URL ending in /exec.

Editing the code changes nothing on its own. Pasting into the Apps Script editor and saving does not touch the /exec URL your pages call — that URL keeps serving the version you last deployed. This is the single most common reason a change appears to do nothing at all.

To publish an edit: Deploy → Manage deployments, click the pencil on the existing deployment, set Version to New version, then Deploy. Leaving Version on the old number redeploys the old code; using New deployment instead gives you a second, different URL and leaves the one your pages use untouched.

Check what is liveopen YOUR_EXEC_URL?action=version — it should answer build: 2026-08-18-photos

No access code is needed for that check. If the build is missing or older, the deployment did not take: repeat the step above. If photos in particular are not arriving, this is almost always the reason — an older deployment does not understand a photo upload and files it in the sheet as though it were a new client.

Then run it once by hand, or photos will never save. Writing to Drive needs a permission the script did not have before, and a web app request cannot ask you for it — it simply fails with you do not have permission to call DriveApp, which looks like a broken feature rather than a missing tick box.

In the editor, choose authorizeDrive from the function dropdown next to Run, press Run, then Advanced → Go to project (unsafe) → Allow. The permission list must mention Google Drive; if it does not, save the file first — Google reads the permissions it needs from the saved code. The function makes a folder and throws it away, so nothing is left behind.

Then checkYOUR_EXEC_URL?action=version should report drive: true

Authorising is per account, not per deployment, so there is no need to deploy again afterwards.

If the console works on one device but not another, this step is almost always why. Who has access must be Anyone — not Only myself and not Anyone with a Google account, both of which let you in and lock everyone else out. There is no per-person or per-device limit in the code: the access code is a single shared password, so the same code works on as many phones and computers as you like. Each device asks for it once, then remembers it.

The other cause is Google being slow to wake a script it has not run in a while — the first load after a quiet spell can take most of a minute. The console now waits 30 seconds and retries once on its own, and it will tell you which of these two it hit instead of blaming your setup.

04

Connect the two pages

Client form: open index.html in any text editor, find const API_URL = "…" near the top of the script, and paste your /exec URL between the quotes.

Dashboard: open dashboard.html and paste the same /exec URL into its own const API_URL = "…" line. That is the only edit — the console then asks you for nothing but the access code, which stays on your device and never appears in the published files.

Optional: in index.html you can also set const COACH_WHATSAPP = "+20…" so the thank-you screen offers a direct message button.

05

Publish on GitHub

Create a repository and upload every file — index.html, dashboard.html, setup.html, support.js and the vendor and assets folders — then Settings → Pages → Branch: main → Save. The vendor folder holds the two React files the pages used to fetch from a CDN; keeping them alongside the site is what makes it load fast on mobile data. assets holds your photos, already cut out and shrunk to a few tens of KB each — they appear on the form, on this page, in the console, and inside every plan you send. You do not upload images or forma_cuts: those are the full-size originals, and only the small versions in assets are ever served.

The dashboard URL is unlisted, not secret — the access code is what keeps the data out of it. Don't share that link or the code.

06

Good to know

Drafts save in the client's browser as they type, so a lost connection never loses their answers. If they hit Send with no internet, the file is queued and goes out by itself when they reconnect.

Every submission carries a submissionId. The script above uses it to ignore a repeat of the same file, so a client tapping Send twice cannot create two rows.

New questions you add to the form appear automatically as new columns in the sheet — no script changes needed.

Google's free quota is far above a coaching business's volume: roughly 20,000 submissions a day.

The form asks for four optional photos — front, back, side, and an InBody sheet. Each one is shrunk on the client's own phone to about 250KB before it is sent, which is what makes this workable on mobile data, and they upload one at a time after the answers are already in your sheet — so a photo that fails can never cost you the file.

They land in a Drive folder called FORMA client photos, one subfolder per client, and stay private: nothing is shared by link. The console fetches them through this same script using your access code, so anyone without that code sees nothing — and a photo URL on its own is useless.
